# Hybrid Energy Optimizer v0.2.1 Historical Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an interactive Streamlit historical DK1 backtest workflow that accepts a hypothetical wind-farm rated capacity and BESS sizing inputs while reusing the existing v0.2 Energinet ingestion and daily backtest core.

**Architecture:** Keep Streamlit as a presentation layer. Add a tested wind-capacity normalization path under `src/energy_hub/data/`, add a small historical-backtest service under `src/energy_hub/backtesting/`, and split the current dashboard into focused page/chart modules. The existing CLI keeps `--wind-share` for v0.2.1 backward compatibility; both CLI and dashboard continue to converge on `run_daily_backtest(...)` and the same optimizer.

**Tech Stack:** Python 3.11+, pandas, requests, Streamlit, Plotly, Pyomo/HiGHS with optional Gurobi, pytest, Ruff, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-01-v0.2.1-historical-dashboard-design.md`

## Global Constraints

- Preserve the current v0.1 synthetic sample workflow.
- Historical market area remains DK1 only in v0.2.1.
- End date is exclusive.
- CI must not call the live Energinet API.
- Historical optimization remains a perfect-information benchmark.
- The hypothetical wind profile must be described as a regional-profile approximation, not real asset SCADA.
- Do not add degradation economics, grid-connection limits, DC-OPF, hydrogen, or scenario matrices in this release.
- Keep `energy-hub backtest --wind-share ...` working unchanged for backward compatibility.
- Version becomes `0.2.1` only after the feature is complete.

## Review Focus

1. Missing installed-capacity month must raise a clear error.
2. Invalid regional capacity factors must raise rather than clip silently.
3. SOC percentages outside 0–100% must be rejected.
4. Incomplete settlement days must still fail the 24-hour validation.
5. Only explicitly mapped DK1 municipalities may count toward installed capacity.

## Task 1 — DK1 installed-wind-capacity normalization

Create `src/energy_hub/data/wind_capacity.py`, extend `src/energy_hub/data/energinet.py`, and add tests. Provide an explicit DK1 municipality mapping, normalize `CapacityPerMunicipality` records, aggregate monthly wind capacity, derive regional hourly capacity factors, and scale them to a user-selected `wind_capacity_mw`. Reject missing/nonpositive capacity and factors outside numerical tolerance. Add `EnerginetClient.fetch_monthly_wind_capacity(...)` and `fetch_hourly_inputs_for_capacity(...)`. Keep existing `wind_share` behavior unchanged.

## Task 2 — Reusable historical backtest service

Create `src/energy_hub/backtesting/service.py` and tests. Add `HistoricalBacktestRequest`, `HistoricalBacktestBundle`, `build_battery_from_request(...)`, and `run_historical_backtest(...)`. Convert SOC percentages to MWh, preserve battery efficiencies/throughput cost from the base config, validate dates and SOC, call the capacity-based Energinet path, then reuse `run_daily_backtest(...)`.

## Task 3 — Split and preserve sample dashboard workflow

Refactor `dashboard/app.py` into a light router, create focused page/component modules, move current v0.1 sample behavior without changing calculations, and extract pure Plotly chart helpers with unit tests.

## Task 4 — Historical DK1 Backtest UI

Add a Historical Backtest tab with DK1, date range, wind-farm MW, battery power/energy, initial/terminal SOC %, and solver inputs. Display days, wind energy, the two baselines, optimized revenue, battery incremental value, total uplift, EFC, four historical charts, and the daily table. Show explicit methodology/limitations. Catch user-facing data/solver errors without raw traceback.

## Task 5 — Documentation/versioning/verification

Update README, bump both package version locations to 0.2.1, run Ruff, pytest, the deterministic sample, compileall, and a short live historical smoke test outside CI.

## Task 6 — PR and branch verification

Compare against updated main, confirm no generated artifacts are tracked, open the implementation PR, require GitHub Actions `test` to pass, review for duplicated optimization logic and scaling assumptions, and merge only through the protected-main PR flow.
