# Hybrid Energy Optimizer v0.2.1 Historical Dashboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an interactive Streamlit historical DK1 backtest workflow that accepts a hypothetical wind-farm rated capacity and BESS sizing inputs while reusing the existing v0.2 Energinet ingestion and daily backtest core.

**Architecture:** Keep Streamlit as a presentation layer. Add a tested wind-capacity normalization path under `src/energy_hub/data/`, add a small historical-backtest service under `src/energy_hub/backtesting/`, and split the current dashboard into focused page/chart modules. The existing CLI keeps `--wind-share` for v0.2.1 backward compatibility; both CLI and dashboard continue to converge on `run_daily_backtest(...)` and the same optimizer.

**Tech Stack:** Python 3.11+, pandas, requests, Streamlit, Plotly, Pyomo/HiGHS with optional Gurobi, pytest, Ruff, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-01-v0.2.1-historical-dashboard-design.md`

## Global Constraints

- Preserve the current v0.1 synthetic sample workflow.
- Historical market area remains DK1 only in v0.2.1.
- End date is exclusive.
- CI must not call the live Energinet API.
- Historical optimization remains a perfect-information benchmark.
- The hypothetical wind profile must be described as a regional-profile approximation, not real asset SCADA.
- Do not add degradation economics, grid-connection limits, DC-OPF, hydrogen, or scenario matrices in this release.
- Keep `energy-hub backtest --wind-share ...` working unchanged for backward compatibility.
- Version becomes `0.2.1` only after the feature is complete.

## Review Focus

1. **Missing installed-capacity month:** the capacity-based path must fail with a clear `ValueError`; it must not forward-fill silently across an unknown month.
2. **Invalid regional capacity factor:** any negative factor or factor above 1.0 beyond numerical tolerance must raise instead of clipping silently.
3. **SOC percentages outside 0–100%:** dashboard/service conversion must reject them before optimization.
4. **Date range with incomplete settlement data:** the existing 24-hours-per-UTC-day validation must still surface a readable error.
5. **Special/non-municipality capacity records:** records not explicitly mapped to DK1 must not be silently counted; the normalization layer must make the DK1 mapping explicit and testable.
